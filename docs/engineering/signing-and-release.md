# Signing and Release Checklist

This document separates repository validation from Apple-account actions. No certificate, provisioning profile, private key, or Apple credential belongs in this repository.

## Current audited target

| Item | Repository state |
|---|---|
| Bundle identifier | `org.garaged.ScaleClimbing` |
| Current version/build | `0.3.0 (1)` — pre-release values; choose the first store version before upload |
| Signing | Automatic; project currently references the prior development team |
| Capabilities / entitlements | None; no entitlements file |
| Permissions | None; generated local audio only |
| App icon | Single 1024×1024 iOS source generated by the project build phase |
| Launch | Generated launch screen; no custom launch assets |
| Release scheme | Shared `ScaleClimbing` scheme archives Release |
| Device family | iPhone and iPad; orientations are declared in target build settings |

## Owner action: configure the new Xcode machine

1. Install the current stable Xcode, open `Apps/iOS/ScaleClimbing.xcodeproj`, and allow Swift Package resolution.
2. In **Xcode > Settings > Accounts**, add the Apple ID that belongs to the organization’s Apple Developer team.
3. Select the **ScaleClimbing** app target, open **Signing & Capabilities**, choose that team, retain **Automatically manage signing**, and confirm the bundle identifier is the registered identifier you intend to ship.
4. Do not add a capability merely to remove a warning. This offline app needs none today.
5. Set the chosen store `MARKETING_VERSION`; increment `CURRENT_PROJECT_VERSION` for every uploaded build, including TestFlight retries.
6. Select the shared **ScaleClimbing** scheme, an iPhone device destination, and **Product > Archive**. Resolve only account/provisioning issues in Xcode; do not commit generated profiles.
7. Validate the archive in Organizer, then upload it to TestFlight only when the App Store Connect record and privacy fields are ready.

## Repository-side validation

```bash
make check
make ios-build
make ios-release-build
make ios-ui-test
make manual-m15
```

`ios-release-build` compiles Release without signing. It validates project configuration but cannot validate Apple certificates, profiles, notarized upload, or App Store Connect state.

## Required release evidence

- Archive succeeds with the owner’s development team.
- Fresh-install launch is crash-free on a current iPhone simulator and physical device if available.
- English and Spanish (Mexico) language passes are recorded.
- No permission prompt, network/account requirement, or unexpected external link appears.
- TestFlight build number and validation outcome are recorded in the release notes / PR.
